StateMachine.h に関する質問への回答
====================================

対象: template<typename OwnerType> class StateMachine の実装
（記事: https://zenn.dev/kd_gamegikenblg/articles/cf0781e4235efa）


1. ラムダ式とは
------------------------------------

名前を持たない、その場で作る小さな関数。基本の形:

    [キャプチャ](引数) { 処理 }

例:
    int a = 5;
    auto f = [a]() { return a * 2; };
    f(); // 10

[ ] の中身が「キャプチャ」。ラムダの外にある変数を、ラムダの中で使えるようにする指定。

  ・[&] … 外の変数を「参照」でキャプチャ。実体そのものを見に行く。
          元の変数が破棄されると危険（ダングリング参照）。
  ・[=] … 外の変数を「値」でキャプチャ。その場でコピーを作る。
          元の変数が破棄されても安全。

実態のイメージ: ラムダ式を書くと、コンパイラが裏で「operator() を持つ、名前のないクラス」を
自動生成している。キャプチャした変数は、そのクラスのメンバ変数として保存される。

    [a]() { return a * 2; }

    ↓ イメージとしてはこういうクラスのインスタンスを1個作っているのと同じ

    class 名前のないクラス
    {
        int a;
    public:
        auto operator()() { return a * 2; }
    };


2. std::function とは
------------------------------------

ラムダ式には「名前のない、その場限りの型」があるため、auto で受けることはできても、
クラスのメンバ変数の型として直接書くことができない。

std::function は「同じ呼び出し方（同じ引数・同じ戻り値）をするものなら、中身の種類を問わず
統一的に格納できる箱」。ラムダ式でも、普通の関数ポインタでも、operator() を持つクラスでも、
形さえ合えば何でも入る。


3. std::function<void()> の void() とは
------------------------------------

< > の中には「格納したい関数の形（シグネチャ）」を書く。

    void()          … 引数なし、戻り値なし
    int(int, int)   … intを2つ受け取ってintを返す

m_fnChangeState は「呼ぶときに何も渡さない、ただ実行するだけの処理」を保持したいので void()。


4. Update() の m_fnChangeState() で何が実行されているか
------------------------------------

ChangeState<T>(...) が呼ばれたときに代入されたラムダそのものが実行される。

流れ:
  1. どこか（例えばStateのOnUpdateの中）で
     m_stateMachine.ChangeState<Player_JumpState>(0,10,3); が呼ばれる
  2. ChangeState の中で「新しいStateを作ってセットする処理」を表すラムダが
     m_fnChangeState に代入される（この時点ではまだ実行されない。予約だけ）
  3. 次にUpdate()が呼ばれたとき、一番最初に m_fnChangeState(); が実行される
     → 予約しておいた処理が、ここで初めて実際に動く
  4. 実行し終わったら m_fnChangeState = [](){}; で「何もしない関数」に戻す
     → 予約消化済みにして、次のUpdateで同じ処理が繰り返されないようにする


5. コンストラクタの引数の初期化（メンバ初期化子リスト）
------------------------------------

    StateMachine()
        :m_fnChangeState([](){})
    {
    }

「:」から「{」の直前までを「メンバ初期化子リスト」と呼ぶ。コンストラクタ専用の書き方で、
「このメンバ変数は、オブジェクトが作られると同時にこの値で初期化する」という意味。

一見これと同じに見えるかもしれないが、厳密には違う:

    StateMachine()
    {
        m_fnChangeState = [](){}; // 中で代入
    }

中で代入する書き方は、実際には
  ① m_fnChangeState をまずデフォルトの状態で作る
  ② あとから改めて代入する
という2段階の処理になっている。メンバ初期化子リストを使うと、最初から目的の値で1回だけ作られる。
単純な型では差を感じにくいが、デフォルトコンストラクタを持たないクラス型のメンバがある場合、
中で代入する書き方だとコンパイルエラーになることもある。

複数のメンバを初期化する場合はカンマで区切って並べる:

    StateMachine()
        : m_pOwner(nullptr), m_fnChangeState([](){})
    {
    }


6. 「:」自体の意味
------------------------------------

単なる書き方の慣習というより、「ここからメンバ初期化子リストが始まる」ことを表すC++の構文。
普通の関数には無い、コンストラクタだけの特別な書き方。


7. ArgTypeがなぜ複数受け取る必要があるのか
------------------------------------

理解はその通りで合っている。Stateごとにコンストラクタが要求する引数はバラバラ:

    Player_StandState();                    // 引数なし
    Player_JumpState(Vector3& a_vec);       // 引数1つ
    Player_JumpState(float,float,float);    // 引数3つ

ChangeState はどんなStateに対しても共通で使いたい1つの関数なので、
「相手のStateが何個・どんな型の引数を要求してくるか分からない」まま呼び出せる必要がある。

可変長テンプレート（ArgType...）を使うことで、ChangeStateに渡した引数の数と型がそのまま、

    std::make_shared<StateType>(a_args...)

を通じてStateのコンストラクタにそのまま転送される。もしArgTypeが無ければ、
引数なしのStateにしか使えず、Player_JumpStateのような引数ありのStateのために
別の関数を用意する必要が出てくる。


（参考）ChangeStateのラムダキャプチャについて
------------------------------------
前回指摘した通り、記事のコードは [&] で a_args をキャプチャしているが、a_args は
ChangeState関数のローカル変数（値渡しの引数）なので、ChangeStateが終了すると消える。
ラムダが実際に実行されるのは後のUpdate()内であり、その時点で参照先は既に破棄されている
（ダングリング参照）。[&] ではなく [=]（値でキャプチャ）にすることで、ラムダの中に
コピーが保存され、後から呼ばれても安全になる。
