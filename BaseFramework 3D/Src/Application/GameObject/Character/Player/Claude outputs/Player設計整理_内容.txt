1. 新しい構造
------------------------------------------------------------

  Player(部品の持ち主。更新の順番を決める・体の操作・被弾)
   ├ PlayerInput        … キー入力を1か所で読む。「押されたか」だけを持つ
   ├ PlayerAttack       … コンボ・チャージの状態。Playerを知らない
   ├ PlayerGuard        … ガードの状態。Playerを知らない
   ├ PlayerSpecialMove  … 必殺技の状態。Playerを知らない
   ├ PlayerHitChecker   … 攻撃判定と「当たった相手の記録」。Playerを知らない
   ├ PlayerSwordTrail   … (変更なし)
   ├ PlayerAnimation    … (変更なし)
   ├ PlayerParameter    … JSON/ImGuiの読み書き。役割別のstructに分割
   └ StateMachine       … 「いつ何をするか」だけを書く

ルールは2つです。
  ・値は、それを使う人が見る(Playerは中継しない)
  ・依存は Player → 部品 の一方向

「Playerに残した関数」と「部品に直接聞く関数」の分け方
  ・体そのものを動かす操作 → Playerに残す
      UpdateMove / UpdateAttackMove / StartJump / StartCurrentAttack
      StartSpecialMove / UpdateAttackCollision / PlayAnimation など
  ・部品の状態を知りたい/変えたい → 部品に直接聞く
      owner->GetAttack().IsChargeComplete()  のように呼ぶ

4. パラメータの持ち方
------------------------------------------------------------
  PlayerParameter を役割別に分けました。JSONとImGuiは今までどおり1か所です。

    BodyParam         … m_maxHP / m_turnSpeed / m_gravityAcceleration
    MoveParam         … m_moveSpeed
    JumpParam         … m_jumpPow
    AttackParam       … m_attackPower / m_attackMoveSpeed
    SpecialMoveParam  … m_attackPower / m_moveSpeed / m_hitCooldownDuration

  各部品には Init() で「自分の分だけ」を const参照(のポインタ)で渡します。
      m_playerAttack.Init(m_parameter.GetAttack());
      m_playerSpecialMove.Init(m_parameter.GetSpecialMove());

  ついでに直したもの
  ・GetParam() が構造体を毎回コピーして返していた → const参照で返すgetterに変更
  ・m_attackMoveSpeed と m_hitCooldownDuration が、JSON保存・読み込み・ImGuiのどれにも
    入っていなかった → 追加しました
      JSONキー: "AttackMoveSpeed" / "SpecialHitCooldown"
      古いJSONに無くても、デフォルト値のまま動きます(contains()で確認)

5. 攻撃データの表化 と コンボ倍率(ご自身で実装する部分)
------------------------------------------------------------
  Attack/PlayerAttack.cpp の先頭に、コンボ段ごとのデータ表を作りました。

      kAttackTable[] = { アニメ, {hitStart, hitEnd, trailStart, trailEnd}, 次コンボ受付フレーム }

  Attack1 / 2 / 3 の値は元のコードと同じです。
  (旧・新の PlayerAttack に同じランダム入力を20万フレーム与え、
   毎フレームの状態が完全に一致することを確認済みです)

  ★ コンボ段ごとに攻撃力を変える手順(新機能なので、ご自身で書いてみてください)
    使うもの:
      1. PlayerAttack.h の struct AttackData
           → 倍率用のメンバを1つ足す
      2. PlayerAttack.cpp の kAttackTable
           → 各行に倍率を書く
      3. PlayerAttack::GetCurrentAttackPower()
           → いまは基本攻撃力を返しているだけ。
             ここで GetCurrentAttackData() の倍率を掛けて返す
      4. Player::UpdateAttackCollision() は変更不要
           → すでに GetCurrentAttackPower() でダメージを取っています
    → Playerは「今コンボ何段目か」を知らなくてよくなります。

    注意(倍率を入れると出てくる罠)
      AttackInfo::damage は int です(Character/AttackInfo.h)。
      10 × 1.25 = 12.5 は、代入した時点で 12 に切り捨てられます。
      float にする場合は、受け取る側も確認してください。
        ・FlyTextManager::CreateDamateText(const int damage, ...) も int
        ・敵・ボスは float の値を int に代入しているだけなので、float化しても互換性はあります

6. PlayerMove / PlayerJump を Player に吸収した理由
------------------------------------------------------------
  この2つは、入力を PlayerInput に移すと中身が2行の関数だけになったためです。
      移動: Player::UpdateMove()     … ApplyCameraRelativeMove + UpdateFacingDirection
      ジャンプ: Player::StartJump()  … 重力をジャンプ力ぶん減らす
  ・PlayerMove.h/.cpp と PlayerJump.h/.cpp は「未使用」のコメントだけにしました。
    ソリューションエクスプローラーで「プロジェクトから除外」して削除して構いません。
  ・もし将来ダッシュなどで移動が複雑になったら、その時にクラスを作り直すのが良いと思います。

7. 挙動が変わった/変わりうる所(小さいもの)
------------------------------------------------------------
  ・ApplyCameraRelativeMove が入力方向(m_moveDir)を上書きしなくなった
      → 同じフレームに2回呼ぶと二重に回る、という順序依存が無くなりました。
        通常の動作は同じです。
  ・必殺技キー('E')の入力を削除
      → IsSpecialMovePressed() はどのステートからも使われていませんでした。
  ・デバッグ用のTキー回復の上限を「固定の100」から「最大HP」に変更
  ・PlayerNormalState 内の「GetStateType() != AttackState」の判定を削除
      → Normalが実行中の時点で、状態は常にNormalなので、常に真の判定でした。
  ・IsGuardHitOrParyy → IsGuardHitOrParry(タイポ修正)
  ・PlayerInput / PlayerActionTiming / PlayerHitChecker は、ヘッダーだけのファイルです。
    .cppを増やすとプロジェクトへの追加が必要になるため、あえてヘッダーだけにしています。
    (ファイルはプロジェクトに追加しなくても動きます。見やすくしたい場合は追加してください)
